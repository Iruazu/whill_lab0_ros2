以下について、`.github/ISSUE_TEMPLATE/task.md` の様式で Issue を起案してください。

対象:
$ARGUMENTS

## 手順

1. `docs/plans/2026-06-11-platform-pivot.md` と、該当フェーズの詳細計画
   (`docs/plans/` 配下) を読む。詳細計画が無ければ先に `pm-orchestrator` で
   計画を作るようユーザーに提案して止まる
2. 1 Issue = 1 ブランチ = 1 PR で完結する粒度に分解する
   (目安: 実装 + レビューが 1 セッションで収まる。受け入れ基準 3 個以内)
3. 各 Issue に「方針文書との対応」(M*/R*/P*) と「前提とする仮定」を必ず書く。
   書けない Issue は粒度か方針側に問題があるので、起案を止めて理由を報告する
4. `gh issue create` で登録し、番号と一覧を報告する。
   gh が使えない環境では本文を全文提示してユーザーに登録を依頼する
5. Issue 間に依存順序がある場合は、各 Issue 本文の末尾に
   「依存: #N の完了後」と明記する
