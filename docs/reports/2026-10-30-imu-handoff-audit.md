# #147 GLIM IMU 調査の引き継ぎ監査

2026-10-30。対象は [Issue #147](https://github.com/Iruazu/whill_lab0_ros2/issues/147)。
> 2026-11-02追記: この監査の結論の一部は、その後の対照実験で訂正した。[原因の報告](2026-11-02-glim-imu-root-cause.md)を見る。

原因確定・修正の受入報告ではない。既存成果物の再解析とソース照合を行った。
実機・runtime 設定・校正値は変更していない。

## 結論

「IMU prediction is not good」だけから「IMU が効いていない」とは判断できない。
既存の300秒 CPU 試行では、最後に表示された回転・速度の予測誤差は
等速予測より小さく、並進の better ratio のみが警告閾値を下回る。
旧 [M5-R 診断](../m5r-imu-diagnostic.md) の回転外部校正への原因断定と
バイアス・雑音設定の除外は、#147 の確定事項として引き継がない。

共通区間の再解析では Hi-Res 補正によって IMU と ICP の不一致が小さくなる。
ただし ICP 自体が校正・deskew の影響を受け、独立した真値ではない。
推定時刻差・外部回転・gyro scale をそのまま実機設定へ転記する根拠はない。

## 警告が測っているもの

`glim/src/glim/common/imu_validation.cpp` の `IMUValidation::validate` を確認した。

- 比較相手は前の姿勢・速度を使った等速並進、姿勢一定の予測。
  別実行の LiDAR-only SLAM ではない。
- 正解の代わりに最適化後の姿勢・速度を比較先にしている。
- 速度0.1 m/s未満は除外。better ratio は開始からの累積で、64回ごとに出力。
- 条件は回転 `>0.7`、並進 `>0.4`、速度 `>0.5` のすべて。
  いずれかが満たされなければ警告する。警告関数自体は IMU を無効化しない。
  `odometry_estimation_imu.cpp` は十分なサンプルがあれば IMU factor を追加する。

既存 CPU 試行の最後の表示（2816 validations）:

| 指標 | 等速予測の平均誤差 | IMU予測の平均誤差 | IMU better ratio |
| --- | --- | --- | --- |
| 回転 | 0.209° | 0.010° | 0.93 |
| 並進 | 0.009 m | 0.009 m | 0.28 |
| 速度 | 0.014 m/s | 0.007 m/s | 0.76 |

並進の平均はログの丸めで同値に見える。これで地図精度や実機受入を証明はできない。

## 時刻・単位・静止区間

既存 `imu.npz` と `scans.npz` を再集計した。
短縮元点群bagのIMU全30000件をSQLite読み取り専用でデシリアライズし、
キャッシュのstamp・加速度・gyroと完全一致することも確認した。

| 項目 | IMU | LiDAR |
| --- | --- | --- |
| 件数 | 216191 | 21311 |
| 実効レート | 99.996 Hz | 9.8575 Hz |
| header 間隔の中央値 | 10.000 ms | 101.445 ms |
| 最大間隔 | 20.031 ms | 102.096 ms |
| header の逆行・同時刻 | 0 | 0 |
| receive − header の中央値 | 0.540 ms | 5.294 ms |

IMUには約20 msの間隔があるので「取りこぼしなし」とは断定しない。
receive 遅延はセンサ間の物理的な同期誤差ではない。

IMU先頭から2〜27秒の2500件の平均加速度は
`[1.335711, -0.525529, 9.794122] m/s²`、大きさ約9.899。
この窓の平均gyroは `[-0.018109, 0.000481, 0.001521] rad/s`。
静止とみなした場合、x方向のオフセットがあり、バイアスを除外できない。
真の静止と取付姿勢の確認なしに、この平均を補正値にしない。

点ごとの `time` フィールドは存在し有限。最小値の中央値は −0.100122 s、
最大値は +0.001306 s。GLIM の負時刻警告はこの入力で説明できる。
`time_keeper.cpp` はこの形式の自動変換を持つため、警告だけを時刻故障の証拠にしない。

## 同一区間での ICP 比較

既存3系列の共通 stamp は `1783663693.922934`〜`1783663813.8347602`、
1183スキャン（約120秒）。全系列で stamp の完全一致を検査した。
既存の `tools/imu_vs_lidar.py` をこの区間で再実行した。

| 点群・ICP処理 | 推定τ | gyro残差RMS | gyro scale | 加速度残差中央値 |
| --- | --- | --- | --- | --- |
| 元の点群・deskewあり | +52.6 ms | 0.0411 rad/s | 1.1122 | 1.041 m/s² |
| Hi-Res補正・deskewあり | +49.6 ms | 0.0274 rad/s | 1.1129 | 0.594 m/s² |
| Hi-Res補正・deskewなし | +44.2 ms | 0.0166 rad/s | 0.9660 | 0.328 m/s² |

τは `LiDAR stamp = IMU stamp + τ` の定義。加速度残差は1.5 Hzフィルタ後、
既存audit外部回転での値。これはGLIMのbetter ratioでも真値に対する誤差でもない。

解析上の制約:

- τは約半スキャンに近い。スキャン中の点の時刻、ICP姿勢の代表時刻、deskewの
  近似が混ざり得るので、`imu_time_offset=0.05` を正解とはしない。
- gyro scale はdeskewの有無で1.113から0.966へ変わる。単位不一致やセンサの
  スケール誤差と断定できない。度/秒とrad/秒の約57倍の取り違えを支持する結果ではない。
- 回転推定は主にyaw励起。特異値の小さい軸があり、全軸の外部校正として採用しない。
- 加速度はICP位置の二階微分と姿勢を使う。ドリフトや微分ノイズが増幅される。
  重力方向の既定値もIMUと設定回転から作るため、完全に独立した符号・校正検査ではない。
- ICP deskewは並進と回転を別々に補間し、scan_dtを0.1014秒に固定する近似。
  出力NPZに生成コマンド全体は保存されていない。ICPの再生成・正解との比較は未実施。
- 床法線とIMU方向の旧出力はHi-Res補正後で約1.1〜1.6°の差だが、床勾配・
  RANSAC・加速度バイアスを分離できず、外部回転誤差の確定値ではない。

## 再現方法と残作業

システムの NumPy 1.21.5 / SciPy 1.8.0 で再実行した。
通常環境はユーザー領域の NumPy 1.26.4 とシステムSciPyの互換性警告が出るので、
この解析だけ `PYTHONNOUSERSITE=1` を指定した。環境のインストール変更はしていない。

```bash
PYTHONNOUSERSITE=1 python3 scripts/imu_investigation/audit_imu_investigation.py \
  ~/bags/imu_investigation_20261030 \
  ~/bags/imu_investigation_20261030/audit_147_new
```

出力先は未作成のディレクトリを指定する。入力のSHA-256、集計、共通区間NPZ、
解析ログ、図を保存する。今回の出力は `audit_147_reproduced/`。
小さなテキスト証跡は [集計JSON](2026-10-30-imu-audit-data/summary.json) と
同じディレクトリの `*_common.txt`、`raw_imu_check.txt` に保存した。
元の解析スクリプトとキャッシュNPZが必要で、bagからICPを再生成する入口ではない。

GLIMのCPU再走も試みたが、DDS初期化で `failed to enumerate interfaces for udp`
となり終了コード250で失敗した（`audit_147/glim_orig.log`）。bag処理には到達していない。
補正前後のGLIM対照実験は未実施。今後は次を順に確認する。

1. 実行可能な環境で保存済みconfigを通常ファイルへコピーし、同じ300秒bagの
   元点群／Hi-Res補正を一条件だけ変えて比較する。実行の終了コードと保存完了を記録する。
2. 同じ入力・設定で時刻処理とdeskewを検査する。オフセットの推定は別区間で検証し、
   補正なしとの予測誤差・地図形状の比較を行う。
3. 静止バイアス、温度・区間依存、雑音設定を分離して検査する。gyro平均を固定で引く
   前にGLIMの推定バイアスと照合する。旧報告の雑音変更のみではバイアスは除外できない。
4. 外部校正はM8-1の実測と整合させ、#135完了後にGPU構成で再現する。
   #147の完了条件（原因と修正先の根拠つき確定）はまだ満たしていない。
