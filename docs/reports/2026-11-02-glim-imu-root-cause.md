# #147 GLIM の IMU：原因の切り分け結果

2026-11-02。対象は [Issue #147](https://github.com/Iruazu/whill_lab0_ros2/issues/147)。オフラインの実験で、実機は動かしていない。校正値と runtime の設定も変えていない。

## 結論

**主な原因は、LiDAR の校正ファイルの誤り（Hi-Res の実機に VLP16db.yaml）。** 点群を Hi-Res に補正するだけで、IMU の予測が等速の予測より悪い状態が解消した。修正先は #144。

IMU の単位、向き、gyro のバイアスが主因であるという証拠は見つかっていない。残る検証は「全行程（2162 秒）でも同じ効果が出ること」で、これは #153 で確かめる。

## 実験

同じ 300 秒の bag（07-10 の先頭、`seg_0_300_orig` と `seg_0_300_hires`）を GLIM の GPU 設定で処理した。変えたのは点群と `fix_imu_bias` の2条件だけで、各条件3回。全12回が終了コード0で、保存まで完了した。

3回の範囲は次のとおり（better ratio は IMU の予測が等速の予測より良かった割合。警告の閾値は回転 0.7、並進 0.4、速度 0.5）。全行の記録は [control_summary.txt](2026-11-02-glim-imu-data/control_summary.txt)。

| 点群 | fix_imu_bias | 回転 | 並進 | 速度 | 速度の誤差 IMU / 等速 [m/s] | 加速度バイアスの最大 [m/s²] | 高さの幅 [m] |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 元 | false | 0.83–0.85 | **0.03** | **0.06** | 0.094–0.097 / 0.026 | 1.01–1.07 | 2.10–3.24 |
| 元 | true | 0.84–0.85 | **0.03** | **0.06** | 0.099–0.112 / 0.026 | 0.65–0.73 | 3.06–4.09 |
| Hi-Res | false | 0.90–0.91 | 0.39–0.40 | 0.62–0.64 | 0.019 / 0.023–0.024 | 0.11–0.14 | 0.88–1.43 |
| Hi-Res | true | 0.90–0.91 | 0.25–0.39 | 0.45–0.62 | 0.019–0.023 / 0.022–0.023 | 0.08–0.12 | 1.00–1.22 |

- Hi-Res・false の r3 は、1度も警告を出さなかった（閾値をすべて満たした）ので比率の記録が無い。上の範囲は r1 と r2 の値。
- 経路長は全条件で 175〜176 m。

## 読み取れること

- **点群の補正の効果は、繰り返しのばらつきより大きい。** 速度の誤差は約 0.095 → 0.019 m/s（約5分の1）になり、等速の予測の約3.7倍から、それ以下になった。推定された加速度バイアスも約8分の1になった。
- **`fix_imu_bias` は主因ではない。** 元の点群では true でも比率は同じ 0.03 / 0.06 のまま。Hi-Res では false の方がわずかに良く、安定している。
- **07-10 の地図の全行程の状態を、元の点群の 300 秒で再現できている。** 全行程の `run.log` の最終値は回転 0.85、並進 0.03、速度 0.07、速度の誤差 0.101 / 0.028 m/s。推定された加速度バイアスは最大約 0.97 m/s²。
- **gyro は問題の中心ではない。** gyro のバイアスは全行程で約 −0.018 rad/s のまま安定していて、静止区間の実測の平均（−0.0181）と一致する。
- **高さの幅が小さくなったことは、精度の証明ではない。** 真値が無く、この区間の実際の高低差も分かっていない。

仕組み（推測、確かめていない）：仰角の誤りで LiDAR の位置推定に系統的な誤差が乗り、それと合わせるために IMU の加速度バイアスが大きく動いて、予測が悪くなる。

## 以前の見立ての訂正

- 「IMU が効いていない見方は支持されない」（[2026-10-30 の監査](2026-10-30-imu-handoff-audit.md)と #147 のコメント）は、短い CPU の試行に基づくもので、補正していない点群の GPU の 300 秒と全行程には当てはまらない。CPU の試行が良かった理由は確かめていない。
- [旧 M5-R 診断](../m5r-imu-diagnostic.md)の「回転校正が真因」は支持しない。T_lidar_imu を変えずに、点群の補正だけで解消した。

## 別に見つかった問題

1. **ローカルの GLIM 設定に、実験の残りがある。** `src/third_party/glim/config/`（git 管理外）は 2026-07-12 に変更されていて、`fix_imu_bias` は `true`（上流の既定は `false`）、雑音は `imu_acc_noise` 0.008・`imu_gyro_noise` 0.0013（上流は 0.05・0.02）になっている。`fix_imu_bias` の固定先は、ソース上は設定の `imu_bias`（未設定ならゼロ）で、`m5r3_run_glim.sh` のコメントにある「初期化後の値」ではない（`odometry_estimation_imu.cpp:263`）。
2. **過去の実行の設定は、記録になっていない。** `glim-out-*/config/` の多くは上流の設定へのシンボリックリンクで、後の変更が見えてしまう。07-10 の `config` は `fix_imu_bias: true` を示すが、同じ実行のバイアスは約 0.97 m/s² まで動いているので、実行時の値は別だった可能性が高い。実行時の雑音の値も分からない。
3. **今回の12回は、上の雑音の値（0.008 / 0.0013）で動かした。** 上流の値との比較はしていない。#153 では設定を確定し、通常のファイルとして残す（`glim_control.sh` は `cp -rL` で固定している）。

## 地図の作り直し（#153）への反映

- 点群を Hi-Res に補正した bag を使う（`scripts/velodyne_reproject_bag.py`）。
- `fix_imu_bias` は `false` にする。
- 雑音の値を決める。実行した設定を通常のファイルとして保存する。
- 全行程で better ratio と加速度バイアスを記録し、今回の効果が続くことを確かめる。

