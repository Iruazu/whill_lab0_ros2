# M8 ロードマップ：デモ後の正常化と比較基準

2026-10-30 策定。課題の正本は GitHub Issues。マイルストーンは `M8-0`〜`M8-4`、`M9`。この文書は、順番とその理由だけを書く。個々の課題の状態は Issue を見る。

## 背景

8月のデモに向けて急いで開発したため、不具合、潜在的な問題、設定と実物の不整合が残っている。問題の多くは、下の層の誤りを上の層の調整で打ち消してきたことに起因する。例えば次のもの：

- LiDAR の校正ファイルが実物と違う（#144）
- LiDAR の TF が実測と違う（#145）
- footprint が車体を覆っていない（#143、#157）

## 方針

1. **下の層から固める。** 順番は「車体とセンサの実測値 → センサの処理 → 地図と位置推定 → 安全と走行 → 比較実験」。下の層の値が確定するまで、上の層のパラメータは調整しない。
2. **main は常にデモができる状態に保つ。**
   - 大きな変更はマイルストーン単位で PR にまとめる。
   - マージの前に、デモ回帰チェック（#142）を通す。
   - 互いに依存する変更は同じ PR に入れる。例えば、LiDAR の校正と TF の変更（#144・#145）と地図の作り直し（#153）は、別々にマージすると NDT が合わなくなる。
3. **屋外での作業は、マイルストーンの区切りでまとめる。**
   - 1回目（#149）：M8-1 の実測値を検証する。
   - 2回目（#156）：M8-2 と M8-3 を受け入れる。
   - 3回目以降：比較実験。
4. **課題は GitHub Issues で管理する。** ラベルは `phase:m8`、`type:*`、`needs:outdoor`、`status:in-progress`。文書に未解決事項の一覧を持たない。
