# Layer D の作動箇所の解析（C3、2026-10-30）

古典的な回避の計画（[計画書](../../plans/2026-10-28-avoidance-baseline.md) §2.2・§4.6）の C3 作業。failsafe の Layer D を、扇形（今の既定）と長方形（`avoidance:=true`）で bag の `/scan` に流し、作動した場所と原因を地図上で確かめた。bag はオフラインで読むだけで、実機は動かしていない。

## 方法

- `scripts/analyze_layer_d_engagements.py`：bag の `/scan` を、`failsafe_node.forward_zone_blocked()` と同じ判定にかける。20 Hz の tick とヒステリシス 0.5 s も node と同じにした。作動（D の立ち上がり）ごとに、`/pcl_pose` から椅子の位置を補間し、帯の中の点の base_link 座標と地図座標を出す。
- 原因の分類（作動した最初の scan で判定）：
  - `mapped_structure`：帯の中の点の半分以上が、占有格子 `docs/maps/campus/occupancy.pgm` の占有セルから 0.25 m 以内にある（地図にある固定物）。
  - `unmapped_object`：それ以外（人・車・置き物・地図にない物）。
  - `single_point_flicker`：1 scan・1 点だけの作動。
- 横の位置：帯の中の点の最小 |y| が 0.5 m 以下なら `in_path`、そうでなければ `beside_path`。
- 操作の状態：`/cmd_vel_teleop`・`/cmd_vel_nav` を 0.5 s 以内に受信していれば teleop・nav、どちらもなければ idle。WHILL のジョイスティックで動かした場合も idle になる。
- 照合のため、`scripts/replay_failsafe_layer_d.sh` で実際の failsafe_node 2 個（扇形・長方形）に `/scan` だけを再生し（rate 2.0、domain 43）、`/failsafe/state` から作動回数を数えた。

## 結果

| --- | --- | --- | --- | --- |
| 07-24 19:05（走行 約500 m） | 843 s | **39 回**（合計 28.9 s） | **3 回**（2.2 s） | 587 件（約 29 s。扇形の再計算と一致） |
| 07-22 seimon 1本目 18:01 | 132 s | 0 回 | 0 回 | 0 件 |
| 07-22 seimon 2本目 18:23 | 160 s | 8 回（27.1 s） | 4 回（17.8 s） | 819 件 |

node の再生でも、07-24 は扇形 39 回・長方形 3 回で、オフラインの再計算と一致した。C0 で記録した「43 回」との差は、帯の外側の境界（r = 1.99〜2.00 m）にある1点が出たり消えたりする場面で、ヒステリシスの切れ目（0.5 s 前後）が再生のタイミングで前後するためと考えられる（扇形の回数は 39〜43 回の範囲で揺れる）。長方形の 3 回は、どちらの方法でも変わらない。

### 07-24（`0724-1905_*`）

- 扇形 39 回のうち **35 回は、発進前（0〜46 s）に (-54.27, 0.27) に止まっている間**に起きた。原因は1つの物で、地図座標 (-55.46, 1.86) にある、地図に載っている固定物。base_link では x 1.83 m、y −0.79 m、r 1.99〜2.00 m で、扇形の外側の角にちょうど掛かる。分類では `mapped_structure` が 17 回、`single_point_flicker` が 18 回になったが、どちらも同じ物。この間の操作は teleop（その場回頭）14 回、idle 21 回。
- 36 回目は 67 s（-53.52, -0.19）で、地図にない物。y +0.73 m で、経路の脇。
- **Nav2 で走った区間（73〜814 s、約500 m）では、扇形も長方形も一度も作動していない**。
- 37〜39 回目と、長方形の 3 回は同じ場面。終点 (-49.4, 0.7) で止まった後の 832〜835 s に、正面 x 1.0〜1.1 m、|y| 0.22〜0.38 m に地図にない物が現れた（人が近づいたと考えられる）。正面の物なので、長方形でも止まるのが正しい。
- つまり、扇形と長方形の 39 対 3 の差は、ほとんどが**止まっている間に、扇形の角に掛かった固定物1つ**によるもの。走行中に止まっていた証拠にはならない。計画書 §4.6 の「この走行の停止の大半は経路の脇にある物で起きていた可能性」は、「停車中の誤作動の大半は」と読み替えるべき。

### 07-22 seimon（`0722-18_01_*`、`0722-18_23_*`）

- 1本目（立ち往生の本体、80〜130 s）：扇形でも長方形でも **0 回**。bag の README の結論（安全層は無関係、塗り境界の inflation と Spin リカバリが原因）と一致する。
- 2本目：停滞していた区間（85〜120 s）では、扇形が 2 回（117.4 s・119.7 s、合計 1.7 s）、長方形は 0 回。どちらも点は r = 1.00 m、x 0.87〜0.91 m、y −0.42〜−0.46 m。扇形は距離 r で判定し、長方形は x で判定するので、この点は長方形の範囲外になる。残りの 6 回（131 s 以降）は、雨のためジョイスティックで北へ退避していた間で、点は正面にあった。長方形も 4 回作動している。
- したがって、07-22 の立ち往生の原因として Layer D は**支持されない**。2本目の停滞区間で長方形にすると防げたのは 1.7 s 分だけ。

## 長方形にしたときの注意

- 長方形は x ≥ 1.0 m で判定するので、r ≥ 1.0 m でも x < 1.0 m の斜め前の点（07-22 の 2 回）は対象外になる。この範囲は、`avoidance:=true` のときに Collision Monitor の PolygonSlow / FootprintApproach が受け持つ（x 0〜1.65 m）。
- 07-24 で長方形の 3 回は、すべて正面の物によるもので、正しい作動だった。
